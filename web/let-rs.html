Prelude

Xsofy is a roguelike where the magic system is the language — flat sequences of runes compile into s-expressions that thread a context through a pipeline of primitives. Let-rs is a clean-room spin-off: same idea, but the substrate is a tiny pure-functional lisp on a CEK machine, written in Rust from scratch, with the spell DSL as its first real client. The point is not to ship anything yet. The point is that the smallest interesting substrate you can call a real programming language fits in a few hundred lines of code, and once you have it, the rest is just a vocabulary of primitives. The second day proved it twice — a second DSL (genomes, codons, Mendelian breeding) shipped without the engine learning a thing about it.

Act I λ

Five rules — the CEK abstract machine, on an index card

The heart of let-rs is Felleisen & Friedman's CEK machine (1980s) — a small evolution of Landin's SECD (1964) and one of the cleanest things anyone has ever written down about how lambda calculus actually runs. Three registers: Control, Environment, Kontinuation. The whole evaluator is a function that takes one of those triples and returns the next one. There is no native call stack. The "stack" is the continuation, reified as plain data on the heap.

⟨x , ρ, κ⟩ → ⟨ρ(x), κ⟩ — variable lookup yields a value ⟨λx.e , ρ, κ⟩ → ⟨Clo(λx.e, ρ), κ⟩ — lambda is a value (closure) ⟨(e₁ e₂), ρ, κ⟩ → ⟨e₁, ρ, Arg(e₂, ρ, κ)⟩ — evaluate fn first ⟨v , Arg(e, ρ, κ)⟩ → ⟨e, ρ, Fn(v, κ)⟩ — then evaluate arg ⟨v , Fn(Clo(λx.e, ρ'), κ)⟩ → ⟨e, ρ'[x↦v], κ⟩ — enter closure body

Five rules. The driver is a four-line loop: 

let mut s = State { mode: Mode::Eval(expr, env), k: Rc::new(K::Halt) };
loop {
    match step(s)? {
        Step::Continue(next) => s = next,
        Step::Done(v)        => return Ok(v),
    }
}

Tail calls fall out for free. When a closure is entered (rule 5), the continuation κ is passed through unchanged. No frame is pushed for the call. A tail-recursive loop counting down from 100,000 terminates in milliseconds with the K-chain depth never exceeding two.

The test tail_calls_dont_grow_the_stack is the proof: it builds the Y combinator in lisp, defines a counter, and runs it 100,000 deep. If TCO were broken the harness would overflow the Rust call stack; it doesn't, because the Rust call stack is never used for lisp recursion in the first place. All the "stack" lives in Rc<K> chains on the heap.

Act II ⌜

The lisp grew up — closures, cons cells, letrec by way of mutable env cells

Atoms and lambdas alone don't make a useful language. The second slice added the pieces that turn a calculus into something you'd actually program in: symbols, quoting, cons cells, variadic arithmetic, the predicate suite (null? pair? number? symbol? eq?), the comparison chain ((< 1 2 3) ⇒ #t), and the binding family: let, let*, cond, letrec.

Three of those are pure desugarings. let becomes an immediately-applied lambda; let* nests one of those per binding; cond folds into a chain of ifs. No new AST nodes, no new continuations, ~20 lines in parse.rs.

letrec is the interesting one. To let a closure see its own name — and its siblings, for mutual recursion — the bindings have to be in scope before any init expression runs. The trick: each environment slot is not a Val directly but an Rc<RefCell<Val>>. letrec allocates a placeholder cell per binding, extends the env with them all, then evaluates the inits one at a time, patching each cell after its corresponding value is computed. Any closure created during init evaluation captures the recursive environment and resolves its siblings through the cells. 

(letrec ((even? (lambda (n) (if (= n 0) #t (odd?  (- n 1)))))
         (odd?  (lambda (n) (if (= n 0) #f (even? (- n 1))))))
  (list (even? 10) (odd? 10) (even? 7) (odd? 7)))
;; → (#t #f #f #t)

At this point the lisp can also host its own library code. map is no longer a primitive — it's six lines defined inside a letrec: 

(letrec ((map (lambda (f xs)
                (if (null? xs) '()
                    (cons (f (car xs)) (map f (cdr xs)))))))
  (map (lambda (n) (* n n)) '(1 2 3 4 5)))
;; → (1 4 9 16 25)

The mutable cells in the env never get touched by anything other than letrec in the current code, so the rest of the language stays observably pure-functional. If we ever add set! it's a fifteen-line addition — the cells are already there waiting.

Act III ⌬

The spell — rune tape, threaded ctx, world transition

This is the part that ties back to xsofy. The player surface is a flat sequence of Unicode runes:

☲ ☲ ☴ 3 ☵ ☳ ☲ ☰ 5 ☶ ☵ ☴ 2

A ~50-line Rust translator (examples/spells.rs) tokenizes each rune through a table: plain runes (☲ → fire) become unary primitives; parametrized runes (☴ → area, ☰ → power) pair with the following numeral. The result is an s-expression that wraps the rune list in a user-level threading combinator:

Each rune is an I Ching trigram whose classical element matches the primitive it names — ☲ Li (fire) for fire, ☵ Kan (water) for ice, ☳ Zhen (thunder) for bolt, ☶ Gen (mountain, stillness) for self, ☴ Xun (wind) for area, and ☰ Qian (heaven, the creative) for power. 

(thread (start) (list fire (area 3) ice))

thread is nine characters of lisp; the primitives are three-line closures over assoc-set; the entire prelude is a single letrec. The engine itself learned nothing new for this — the spell DSL is a vocabulary on top of the lisp, not a modification to it.

Once a spell has been evaluated it's a ctx — an associative list of (key, value) pairs accumulated by each primitive in turn. A second primitive, (world-apply! ctx), is the resolver: it reads element, tx, ty, area from the ctx and paints a square neighborhood of the host's grid world. 

== cast 'ice (area 2)' at (3,2) ==
→ 25 tiles painted
.ooooo.

.ooooo.
.ooooo.

log:
  · cast fire at (1,1) area=0 life=5 → 1 tiles
  · cast fire at (4,2) area=1 life=5 → 9 tiles
  · cast ice  at (3,2) area=2 life=5 → 25 tiles

Notice what happens when a tape mentions two elements: ☲ ☴ 3 ☵ produces a ctx with both (element . fire) and (element . ice) still present. The resolver currently takes the freshest, but the older binding hasn't been erased — it's structurally still there. This is where the emergent payoff lives: a smarter resolver could see both and fork the spell into two effects, blend, or pick a winner by context. Same DSL, different semantics, no engine change.

The split between the language and the host is the design decision that makes this scale. The lisp returns a ctx — pure data, no side effects, replayable. The host decides what that ctx means this turn. Spells are testable in isolation; the pipeline is pure right up to the world-apply! resolver, where the host commits. True rollback after a commit needs a world snapshot — that’s an open ticket, not built today.

Act IV ∮

The lisp learns to extend itself — defmacro, quasiquote, the moment syntax becomes a library

A lisp without macros is a calculator with parentheses. The macro system is the moment the language stops being something the host defined and starts being something the user can extend at compile time.

Macros in let-rs are procedural — every macro is a regular closure that runs at compile time, takes the raw s-expression arguments as quoted data, and returns a new s-expression to be compiled in its place. The implementation is ~80 lines on top of the existing machinery. defmacro is a top-level form; the Vm holds a HashMap<String, Macro> alongside the env; eval_str walks the datum tree first, expands any list whose head is a registered macro, and only then calls parse::compile.

Quasiquote is the ergonomic companion: `(if ,c ,t #f) parses to (quasiquote (if (unquote c) (unquote t) #f)) and compiles to a runtime expression that builds the list with c and t evaluated. With ,@ splicing for variadic positions. 

(defmacro -> args
  (letrec ((step (lambda (acc form)
                   (if (pair? form)
                       (cons (car form) (cons acc (cdr form)))
                       (list form acc))))
           (loop (lambda (acc fs)
                   (if (null? fs) acc
                       (loop (step acc (car fs)) (cdr fs))))))
    (loop (car args) (cdr args))))

;; (-> 5 (+ 3) (* 2))  expands to  (* (+ 5 3) 2)  evaluates to  16
;; (-> 10 inc inc inc)  expands to  (inc (inc (inc 10)))  →  13

That -> is the thread-first operator from Clojure, built in lisp from scratch. The trick xsofy uses to compose spell primitives — (-> ctx fire (area 3) ice) — is now expressible as user-level syntax, not a special form baked into the engine.

Hygiene is not implemented. A macro that introduces a binding named tmp can shadow a tmp at the call site. This is the standard Common Lisp tradeoff and intentional for a learning project. Gensyms or syntax-rules would be the next step, but every macro we've actually wanted so far has been hygiene-safe by construction (single-pass templates, no fresh bindings).

With macros in the language, the special-form list in parse.rs shrinks to just the things that can't be desugared:

  1. lambda · if · quote · letrec primitive — these define the calculus
  2. quasiquote · unquote · unquote-splicing primitive at the parse layer because they need data, not values
  3. defmacro top-level only; registers a closure in the macro table
  4. let · let* · cond desugared at parse time; could be macros instead, currently kept in Rust for clearer error messages

Everything else — when, unless, and, or, the threading combinators, eventually defspell itself — lives in user code. The syntax of the spell DSL becomes a library, not a fork of the parser.

Act V ⊛

A second vocabulary — genes, codons, Mendelian segregation, the substrate proves itself

The spell DSL was the first user of the lisp. To know whether the design holds you need a second user that looks nothing like the first. Day two added it: genetics. Codon tapes (AUG CGA GCA … UAA) compile to a list of trait-applying closures, an express! resolver folds a genome into a single phenotype, a mutate! primitive drifts alleles at a rational rate, and a breed! primitive crosses two parents under Mendelian segregation. The engine learned nothing new for any of it.

AUG CGA GCA ACA UCA GCG AUC GAU UAA

That tape — a "balanced" creature — runs through the genes prelude and emerges as a small ASCII card: 

╭─ creature #1c7a ─────────────────────────────╮
│ size  70  strength  75  speed  80  armor  60 │
│ color green     ability fire-breath          │
│ biome volcanic                               │
│     (◉ ◉)                                    │
│     ▼▽▼                                      │
╰──────────────────────────────────────────────╯

A tape with two alleles per locus — a diploid genome — exercises the resolver's interesting cases. Numeric traits average across the two alleles. Categorical traits follow textbook dominance: dom wins over rec; same-kind ties are broken deterministically by an FNV hash of the genome so the same input always produces the same creature. Append a MUT codon and the prelude's mutate closure drifts every allele with seeded xorshift — same seed, same drift. Cross two parents through breed! and each locus picks one allele from each parent at random, giving the offspring a fresh diploid genome that can be expressed, mutated, or re-bred. 

(express! (mutate (breed! seed
                  (thread '() mama-strand)
                  (thread '() papa-strand))))
;; → phenotype alist → render_creature → ASCII card

The whole vocabulary is twenty lines of prelude plus three pure Rust prims (express!, mutate!, breed!). It uses nothing from the spell stack — no World, no WorldPrim, no host state at all. The substrate held: Vm ran a structurally different DSL without an engine change. The spell DSL is last-write-wins flat alist; the genes DSL is list-per-key diploid accumulation with hash-deterministic tiebreaks. They share the lisp underneath and nothing else.

The architectural lesson written down in ADR-011's "promote when a second consumer appears" rule had its first real test here: the rune translator (crates/runes/) got pulled into a sibling crate when the WASM bridge became a second consumer; the spell prelude (spells::PRELUDE_DEFINES) got hoisted into the lisp crate; the genes vocabulary (lisp::genes) similarly. The rule kept the deduplication honest — never one consumer ahead of an abstraction. Update 2026-05-29 (ADR-016): the same rule fired again — both DSL packs are now sibling crates (crates/spells/, crates/genes/) parallel to runes and codons. The lisp crate is "engine + parser + numeric tower" again and ships no demo vocabulary.

What this also surfaced, quietly: the second consumer of Vm didn't want a tile world. The engine's fixed World type — a paintable grid plus an event log, named aspirationally in Act III — turns out to be the spell demo's host state, not a general concept. The genes demo carries a 0×0 World::empty() as dead weight. docs/project_notes/host-state.md captures the design conversation; the host-agnostic-Vm refactor it points at is the next big slice. Update 2026-05-29 (ADR-017, ADR-018): the slice landed. Val::WorldPrim collapsed into a single closure-capable Val::Prim carrying Rc<dyn Fn>; Vm.world was dropped; the engine no longer knows World exists. world.rs moved to crates/world/ as a sibling micro-crate. Hosts wire grid prims in via world::world_prim::install(&mut vm, world) — or call the one-line spells::install_with_world convenience.

Act VI ⫯

The engine grows up — installable preludes, exact rationals, mutual recursion at the top level

Three engine additions came in alongside the second DSL, each one driven by something the second DSL exposed. None of them changed the CEK rules. All of them sharpened the seam between "language" and "vocabulary."

Installable preludes

Both DSLs were initially shipping their preludes as open letrec source strings that the host had to append a body and a closing paren to. Every cast() retokenized, recompiled, and re-evaluated ~25 lines of prelude. With WASM in the loop this was the dominant per-call cost. The fix: eval_str now accepts a sequence of top-level forms, including a new (define name body) form that extends the Vm env in place. Each DSL crate exposes an install(vm) that runs its prelude defines once at startup. A DSL is now "a const string + an install function" — two lines to add a new pack to a Vm. 

let mut vm = Vm::new();
spells::install(&mut vm);   // installs spell vocabulary
genes::install(&mut vm);    // installs gene vocabulary
// each cast()/cast_genome() now carries just the body

Exact rationals

The genes mutate! prim wanted a 5% mutation rate and had to take 5 (integer percent) because the only numeric type was i64. The first place a non-toy demo asked for a fractional value, the language couldn't say it. So Val grew a Ratio(i64, u64) variant — exact, always stored in lowest terms with positive denominator, collapsing to Num at construction if the reduced denominator is 1. The parser reads 1/4 literals. Arithmetic uses i128 intermediates and a Euclidean gcd for normalization. / became exact division — (/ 1 4) → 1/4, no more integer-divides-and-rounds. The genes prelude now reads (mutate! 1/4 seed ctx) instead of (mutate! 25 seed ctx), which is what the doc had wanted to say all along.

A 99-step rational fold ((+ 1/2 1/3 … 1/100)) benches only ~10% slower than the equivalent integer fold. The i128 + gcd pipeline is cheap enough on small numerators that the numeric tower didn't introduce a real performance cliff.

Mutual-recursive top-level defines

The initial (define name body) only supported self-recursion via a placeholder cell — fine for (define f (lambda () (f))), but (define even? …) (define odd? …) would fail because even?'s closure captured an env without odd?. A pre-pass over the parsed forms now allocates placeholder cells for every top-level define before any body evaluates, so siblings in the same eval_str call freely refer to each other. The cross-call case (define foo in one REPL line, define bar in the next, expect foo to call bar) initially didn't work — closures captured env at evaluation time. ADR-015 closed that gap the same day, as a side effect of moving top-level bindings into a Vm-owned globals table that every Env points back to via a Weak. Closures now resolve forward references at call time against the table's current contents, so the REPL-line case works freely — and the original limitation test got flipped to assert success.

The supporting cast: a shared assoc-get pure prim that both demos now use instead of redefining locally; numerator, denominator, floor, ceiling accessors for rationals; Val::cons and Val::alist_from constructor helpers that eliminated Val::Cons(Rc::new(…), Rc::new(…)) long-hand from every Rust call site; a benchmark crate (crates/bench/) with thirteen criterion benches covering the engine and both DSLs so the next refactor has numbers to compare against.

The "Vm + DSL pack" idea is real now. A vocabulary is no longer a fork of the parser or a special wrapping expression — it's a const string of defines and a handful of pure prims, installable in two lines. Two DSLs on day two; the third one is just paperwork.

Act VII ⎈

The fourth register — the store arrives; the letrec cycle dissolves by construction

The shortlist that closed the last chapter named a known weakness: the letrec Rc cycle. A closure that captures the env containing its own placeholder cell forms a ring — cell → Val::Clo → env.frame → cell — that nothing breaks. ADR-021 pinned it with a diagnostic test and parked the fix; the cleanest available cure was a Y-style desugaring pass nobody wanted to write unless they had to.

The cleaner cure turned out to be one letter further down the alphabet. CEK threads three explicit registers (control, environment, continuation); CESK threads four. The new register is a store: a heap of values owned by the Vm, indexed by a Copy Addr(u32). Frame slots stop being Rc<RefCell<Val>> cells and become plain Addrs. The closure → env → frame → Addr → store path still exists; what's gone is the Rc edge at the far end. Addresses don't hold anything alive, so closures can't root their own cells anymore. The cycle dissolves by construction — not by patching the engine, by moving where the values live.

The migration came in smaller than the design estimated: a new store.rs (≈50 lines), one retyped field in Frame, K::Letrec.cells renamed addrs, and a second Weak in Env — alongside the existing back-edge to globals — that points at the store. The five CEK transitions stayed five; step, run, and run_bounded kept their signatures because the store is reachable through any env it threads. The ADR-021 diagnostic flipped from letrec_cycle_persists_after_drop to letrec_does_not_leak and asserts the opposite property: drop the Vm, the store drops with it. 121 tests passed on the first run. Globals kept their Rc<RefCell<Val>> shape — the ADR-015 Weak back-edge already worked there, and not touching it was the right call.

The chapter that opens here isn't written yet. set! is now five lines. The CEK State is plain data you can clone, which puts undo and replay scrubbing for the labs on the roadmap as a real thing rather than a wistful aside. Persistent stores — a HAMT under the Vec<Val>, for O(log n) snapshots — are the natural follow-on if any of that pulls. The five transitions are still five transitions. The substrate just grew a register.

Act VIII ⊢

The vocabulary becomes a library — macros to a sibling crate, defspell ships, the expander grows up

Act IV ended on a promise: defspell itself would eventually live in user code. Three acts later it does — and getting there meant first asking a harder question about the engine itself.

The audit started with a one-line observation. The macro system was about half the engine, and most consumers never registered a macro. Of the four DSL packs — runes, codons, strokes, plus the host-side world — none used defmacro. Only the user-facing REPLs (web bridge, examples/repl.rs) did. Every other host paid for the Vm::macros field, the expansion pass, the snapshot restore, the val_to_datum round-trip, and got nothing for it. That's drift. The original thesis was smallest interesting substrate; a substrate that ships features half its consumers don't use isn't smallest anymore.

ADR-024 made the cut. crates/macros/ got the Macro struct, the Expander with its HashMap<String, Macro> table, the four walks (expand_all, expand_in_qq, expand_macro_call, try_register_defmacro), and val_to_datum. A new MacroVm wrapper bundles a lisp::Vm with an Expander and offers a macro-aware eval_str. The engine itself reverted to macro-unaware — its eval_str_inner now just compiles each form. A pinning test (defmacro_unknown_to_raw_vm) asserts a raw lisp::Vm rejects (defmacro …); any regression that pulls macros back into lisp flips it.

Parser-level quasiquote stayed in lisp/parse — backtick, comma, comma-at compile to list-construction expressions and work without macros installed. What moved is the expansion pass, not the syntax. The parser still reads `(1 ,x 3) as a runtime call to list; the macros crate is what walks a datum tree looking for macro calls inside it.

Once the macros crate was its own thing, a small standard library wrote itself. install_stdlib registers five macros — begin, when, unless, and, or — written in lisp inside a const STDLIB: &str. begin in particular closes a ticket that had been open since ADR-019: the standing (let ((_ a)) b) sequencing workaround. The engine never grew a begin special form — the macro is enough, and putting it in the macros crate rather than the parser honored ADR-019's deferred-then-rejected decision exactly. Hosts opt in: MacroVm::with_stdlib(), or install_stdlib(&mut vm) on a plain MacroVm::new(). A pinning test (stdlib_not_present_without_install) keeps the opt-in discipline honest.

defspell, as promised

With the substrate in place, the rune prelude was the natural first adopter. The old prelude was nine repetitions of two shapes — four constant ctx-setters (fire/ice/bolt/self) and two parametric ones (area/power): 

(define fire  (lambda (ctx) (assoc-set 'element 'fire ctx)))
(define ice   (lambda (ctx) (assoc-set 'element 'ice  ctx)))
(define bolt  (lambda (ctx) (assoc-set 'shape   'bolt ctx)))
(define self  (lambda (ctx) (assoc-set 'target  'self ctx)))
(define area  (lambda (n) (lambda (ctx) (assoc-set 'area  n ctx))))
(define power (lambda (n) (lambda (ctx) (assoc-set 'power n ctx))))

Two shapes, repeated. ADR-025 ships what Act IV named: 

(defmacro defspell (name key val)
  `(define ,name (lambda (ctx) (assoc-set ',key ',val ctx))))

(defmacro defparam (name key)
  `(define ,name (lambda (n) (lambda (ctx) (assoc-set ',key n ctx)))))

(defspell fire element fire)
(defspell ice  element ice)
(defspell bolt shape   bolt)
(defspell self target  self)
(defparam area  area)
(defparam power power)

The two macros are spell-DSL-specific — the assoc-set call shape is the spell ctx convention, not a general lisp pattern — so they live in the spells prelude rather than the macros stdlib. Adding a new rune that stamps a constant key into ctx is now one line. The shape that had been a repeated incantation is the macro; the macro is the vocabulary; the vocabulary is a library. That's the loop Act IV named and Act VIII closes.

A bug that surfaced exactly when it should have

The adoption surfaced something the original macros crate hadn't noticed because nothing exercised it. The Expander had a guardrail — "define at any list head is an error" — meant to catch the (let ((x 1)) (define y 2)) mistake. That rule was correct in expression position. It was also correct at top level by accident: no MacroVm consumer had ever installed a prelude through it. The genes and curves preludes went through the raw lisp::Vm directly, and the web REPL evaluated user expressions, not defines.

defspell changed that. A top-level (defspell fire element fire) expands to (define fire (lambda (ctx) (assoc-set 'element 'fire ctx))), and the recursive call into expand_all on the expansion hit the guardrail. The first install of the spells prelude under MacroVm returned define only valid at top level — which was both wrong (the define was at top level) and right (the expander had no concept of top-level position).

The fix split the entry point in two. expand_top_level handles the outermost call from MacroVm::eval_str_inner: it keeps a top-level (define name body) intact, recursively expands the body forms (where the no-nested-define rule still applies), and — for macro calls — re-enters at top level after expansion so a macro whose result is a define is allowed. expand_all continues to reject defines in expression position. Three regression tests pin all three cases: top-level (define …), a macro whose expansion is a top-level (define …), and the inverse — (let ((x 1)) (define y 2)) still errors.

The engine is smaller, the vocabulary is a library, and the expander is honest about what "top level" means. Act IV promised a substrate where the spell DSL's syntax was a library, not a fork of the parser; Act VIII ships the proof. The natural next adopters — defcodon for the genes prelude, defstroke for curves — are obvious from here. Neither is urgent. The pattern is real now; the rest is paperwork.

Act IX ⟳

The world learns time — set!, decay, mana, aftershocks, alchemy

Every act until now kept the surface purely functional. The Spell Lab painted tiles and they stayed; a cast was a snapshot, not a move. The dynamic-spells arc — six ADRs across two days — turned that snapshot into a loop, and it started by adding the one thing the language had refused to have: mutation.

ADR-026 · set!. The CESK store landed back in Act VII precisely so a binding could be mutated without rewinding the environment's shape — but nothing spent that affordance. set! is the form that does. It compiles to a fifth continuation, rebinds an existing slot (a frame Addr or a globals cell), and is the only effecting form in the language; everything else stays expression-pure. It also retired the old (let ((_ a)) b) sequencing hack — with a real effecting form, sequencing is honest.

ADR-027 · decay. With mutation in hand the world could hold time. Every tile carries a u8 lifetime; (world-tick!) decrements each one and reverts it to floor at zero. The central interaction stops being "paint and it persists" and becomes cast → watch it fade → recast. A spell's power feeds that lifetime, so a stronger cast simply lingers longer.

ADR-028 · mana. Decay made the world temporal; mana made the caster finite. Two caster-side globals — max-mana and mana — are spent by cast! and regenerated by tick!, thin wrappers over the world prims that set! the counter. That closes the loop the arc was chasing: cast, spend, wait for the tick to refund you, cast again. The Lab's mana 10 / 10 meter is those two globals, live.

ADR-029 · aftershocks. The ☱ Dui (lake) trigram schedules a cast to re-fire N ticks later — a fire that reignites after it dies, an ice patch that blooms twice. An exploratory split of duration out of power got reverted here on a point of taste: in the spell DSL, power should mean "how long this lingers," because that is what the rune says. The coupling was intent, not accident.

ADR-030 · alchemy. The element runes stopped overwriting the context and started mixing with it. Fire on ice yields water; fire on earth, lava; and the mixes cascade — fire + ice → water, then water + earth → mud — because each element folds into whatever the ctx already holds. Two of the four "plain" runes had been aspirational placeholders since Act III; alchemy gave them a job, and gave the resolver a reason to grow its Tile enum past the original four.

ADR-031 · strings. A quieter, later addition: the ninth Val variant. The engine had lived on eight, with symbols standing in for text and paying for it — a symbol prints as an identifier and won't round-trip through read with a space in it. Val::Str (an Rc<str>, self-evaluating, content-compared by eq?), plus "…" in the tokenizer and six string prims, closed that gap without touching the CEK rules.

set! aside, none of this is an engine rule — decay, mana, aftershocks, and alchemy are all vocabulary and host state layered on the substrate Acts I–VIII built. The through-line held: the world got a heartbeat, a budget, and a chemistry set, and the five transition rules never moved.

Act X ⊓

The guarantees go stale — a budget that counts the wrong thing; a rollback that outlived its language

Nine acts of building, then an afternoon of trying to break it. Most of what fell out was ordinary — a lifecycle slip in the Spell Lab's tick loop, a missing checked_add in the genes resolver, comments that had drifted a release behind their code. Two findings were more interesting, and they were the same finding twice: a guarantee that was true when it was written and false by the time anyone read it. Nothing had gone wrong with either guarantee. The language moved underneath them.

A budget that counts the wrong thing

The CEK step budget is the substrate's answer to hostile input. The browser evaluates on the main thread, so an unbounded loop doesn't fail — it hangs the page. Capping a run at ten million transitions turns that into an error message. It is the stated safety net at the untrusted boundary, and it works.

It counts steps. The Curve Lab's canvas is sparse — a hash map holding only the cells the turtle has stamped — and its renderer is dense: a grid spanning the bounding box, spaces where nothing was drawn. For most curves those are the same order of magnitude. For a diagonal they aren't. N stamped cells span an N×N box, so the turtle grows linearly while the thing that prints it grows quadratically, and nothing in the code connected the two.

(grow '(+ F) '((F F F)) 14) is 16,384 strokes. That sits comfortably inside ten million steps — the budget never blinks — and it asks the renderer for a 268-million-cell grid, about a gigabyte. The tab stops responding. The safety net had a hole in it exactly the shape of memory, because it had only ever been asked about time.

The page had a second bound, missing in the same direction: max="6" on the iterations input, which browsers enforce for the steppers and for form validation but not for a value someone types. Two independent limits, both absent along the same axis.

render now returns a Result and refuses a bounding box over two million cells, checked before it allocates rather than after. The guard is a transplant, not an invention — World::new has had one since the grid became reachable from JavaScript, for the same reason. What was missing wasn't the idea. It was noticing that a second surface had grown the same exposure.

A rollback that outlived its language

Back in Act VI, eval_str learned to undo itself. A failed (define + (/ 1 0)) used to leave a placeholder cell shadowing the builtin +, which took down every subsequent REPL line — one typo and the session was over. The fix snapshots the globals table before the batch and restores it if any form errors. It's cheap because unchanged cells are shared rather than copied: the snapshot bumps refcounts, not values.

That sharing is precisely what broke it. Act IX added set! — the language's only effecting form — and set! writes through the shared cell. So (set! x 99) (car 5) fails the batch, the rollback runs, and x is still 99. The snapshot restores which cell each name points at. It was never restoring what's inside them; until Act IX, nothing could tell the difference.

Not one line of eval_str changed. Act IX broke Act VI's promise at a distance, and the docstring went on saying atomic for two acts. The fix is a smaller claim rather than a bigger mechanism — real transactional rollback wants the persistent store ADR-023 left open, and even with it the host's painted tiles and turtle state would still stand. Better to document a narrow guarantee that holds than a broad one that doesn't.

Neither guarantee was wrong, exactly. The budget still catches the loop it was built for; the rollback still keeps a failed define from poisoning a REPL session. Both were just narrower than their wording — and a docstring is the one part of a codebase that never fails a test. Both have tests underneath them now, which is the whole difference between writing a guarantee down and actually having one.

Act XI ⊘

Three things the record got wrong — a leak traded for a leak, a correctness bug filed under performance, and a vector per name

Act VII ends in triumph. The letrec cycle that ADR-021 had pinned and parked dissolved by construction the moment frame slots became Addrs instead of Rc<RefCell<Val>> cells. The diagnostic flipped from letrec_cycle_persists_after_drop to letrec_does_not_leak. 121 tests passed on the first run.

The test was passing for the wrong reason. The cycle was gone because nothing was ever freed.

The store as ADR-023 specified it was append-only. Slots went in; no slot came out. Before the migration a frame's cell died with the frame, and only the letrec cycle leaked. After it, every binding the machine ever created stayed allocated for the life of the Vm. A conditional leak had been traded for an unconditional one — in exchange for snapshot and undo capabilities that, four acts later, still hadn't shipped.

Five lines of scratch test made it plain. A ten-thousand iteration loop cost twenty thousand and two slots; running it a second time cost twenty thousand and two more. Nothing about that is subtle — it's the first thing you'd check if you thought to check it. The Spell Lab drives (tick!) on an interval in a page meant to be left open; the browser REPL's budget is ten million steps, so a single (loop 1000000) permanently added two million values to a machine that lives as long as the tab.

Who owns a slot

The fix follows from a question the original design didn't ask: who owns a store slot? A Frame does, and uniquely — extend_addr is the only place a frame is built, and every call site hands it a freshly allocated address. So when the last Env naming a frame drops, that slot is unreachable and can go back on a free list. Forty lines. The eighty-thousand-slot figure becomes a high-water mark of four.

The ADR said this restored the pre-CESK behavior exactly. A reviewer disagreed, in three lines: (letrec ((f (lambda () (f)))) 0), evaluated a hundred times, retains a hundred slots. The frame's destructor is what frees the slot — and the closure sitting in that slot captured the frame, so the destructor never runs. Choosing the frame's death as the trigger made the slot's liveness depend on the frame and the frame's liveness depend on the slot's contents. That is the ADR-021 cycle, third sighting: pinned in one act, declared dissolved in another, and still here.

It's bounded — one slot per recursive closure, not per iteration — and it isn't a regression, since the append-only store retained these too along with everything else. The preludes never touch it; they build vocabulary with top-level define, which lives in the globals table rather than in frames. So the fix stands and the claim was wrong, which are different things. The claim is now the narrow one, the residual has a test asserting it so a future fix breaks loudly, and the real cure — a trial-deletion sweep at top-level form boundaries, where the continuation is Halt and the roots are finally enumerable — is written up and shelved.

The tell, in hindsight: the reclamation test exercised one frame shape, a top-level define, whose closure captures the root env and therefore cannot form the cycle. One shape tested; the shape that mattered, not. It now covers five.

Two things bite on the way. Releasing a slot drops the value in it, and that value may be the last owner of a closure whose env holds frames — which re-enters the free path mid-borrow_mut and panics. Both free and set now take the displaced value out under the borrow and drop it after releasing. And once slots are recycled, an Addr that outlives its frame reads a different binding instead of faulting. Nothing in the engine holds an Addr without also holding the Env that keeps its frame alive — except one public accessor, added for diagnostic tests and never used by one. It's gone.

The cost that was filed under the wrong heading

One layer up, the same afternoon, a second one. Act VIII moved macros to their own crate, and because eval_str was the only public door into the engine, the expander had to hand its output back as source text — serialize every expanded form and let the reader parse it a second time. Act VIII noticed, wrote it down as a cost, and deferred the fix: worth doing if a benchmark shows the round-trip is measurable.

Which filed a correctness bug under performance. Act IX had already written down the reason, in the first paragraph of the ADR that added strings: a symbol with a space in it doesn't survive a round-trip through read. Act VIII then made read the transport for macro output. Two acts, each holding half the answer, neither citing the other.

It takes one line of lisp to fall over. (string->symbol "a b") builds a symbol the printer can't represent; (quote |a b|) prints as (quote a b) and re-reads as a two-argument quote. Any macro that derives a name from a string — which is what a defsomething macro is — hits it. The fix is the entry point Act VIII already knew it wanted: eval_datums, the expander hands over datums, the printer leaves the path. Preludes install about a fifth faster, which is the part that would have shown up in the benchmark, and the least interesting thing about it.

Act X was about guarantees that went stale: true when written, false by the time anyone read them. These are worse and more interesting. ADR-023 has an alternatives-considered section with four entries and a consequences list with eleven, and not one of them is the store never frees anything. The document wasn't overtaken by later work. It was incomplete on the day it was written, and thorough enough that nobody went looking. That's the failure mode of a good ADR habit: prose that careful starts to feel like proof. No amount of it found this. A five-line test did, in about a minute.

What the machine allocates per name

Then the third one, which nobody had written down at all — because nobody had asked the machine a question it could answer. Not is this correct but what does this allocate.

Val::Clo held its parameter names in a Vec. Val is Clone, and looking a name up copies the value out of the store — so every mention of a function name, not every call, heap-allocated a fresh vector of its parameter names. Meanwhile apply_k matched the continuation by reference, which left it no choice but to clone both of K::App's vectors on every single argument: an n-argument call cost O(n²) value clones. It had survived eleven acts because nothing in the benchmark suite takes more than three arguments.

The fix is one idea applied in three places: share what's immutable, own what's consumed. Parameter lists and subexpression lists become Rc<[…]>, shared between the AST and the continuation walking it. The remaining field disappears entirely — evaled fills left to right, so its length is the index of the expression in flight. And apply_k takes the continuation by value and unwraps the Rc: with no first-class continuations, every frame is uniquely owned by the one state about to consume it, so the fields can simply move. Between 1.5× and 3× faster on every core workload, for a change with no semantic surface at all.

Three findings, one shape. The first was a document incomplete on the day it was written. The second was complete and sized and attached to the wrong test for whether it mattered — a benchmark that was never going to fire, for a problem that was never about speed. The third was the one the benchmarks would have caught, if any of them had passed more than three arguments to anything. The record was good enough to trust in all three cases. What it wasn't, in any of them, was checked against the machine. The store had one honest number in it the whole time; the expander had one line of lisp; the CEK loop had a profiler and thirty-two arguments.

And then the ADR written to say so did it too, in the same afternoon, and needed a reviewer with a three-line letrec to find out. Which is the actual lesson, later than it should have arrived: knowing the failure mode confers no immunity to it. The only thing that has caught any of these is someone running the code and looking at the number.

Act XII ⏸

Two claims, unspent — an error that wouldn't say where, and a machine that could always stop

Both of these had been sitting in the coda below. One of them — structured errors — has been the first item on that list since the day it was written, and for two months the project notes said it was half-finished, which it wasn't; not one line of it existed. The other was never on the list at all, because ADR-001 had already claimed it. The very first design document describes the machine as trivially pausable, serializable, time-travel debuggable. That sentence had been true and unexercised for eleven acts.

Acts X and XI were about a record that had drifted from the code. This is the opposite failure and a cheaper one: a record that was accurate about capabilities nobody had spent. The engine really could stop between any two transitions. Nothing had ever asked it to.

An error that wouldn't say where

Every error in the workspace was a String. A missing paren in a forty-line prelude reported exactly unclosed (. An unbound variable reported exactly unbound variable: foo. Both messages are true, and neither tells you where to look — which is the difference between a language you can demo and one you can debug in.

The mechanical part is a struct with a message and an optional span. The part that decides whether the whole thing works is one method: attach a position only if there isn't one already. With that, the compiler needs exactly one place that annotates anything — compile_inner(d).map_err(|e| e.with_span(d.span)) — and every helper below it inherits positions for free. Without it, an error raised inside a nested if gets re-stamped by the enclosing lambda, then by the enclosing define, and arrives reported at line 1. The obvious spelling of that line is assignment, and assignment is how you build a compiler that thinks every mistake happened at the top of the file.

The second decision was admitting that no position is a real answer rather than a gap to be filled. Macro expansions and forms a host assembled in Rust have no source text. They report without a position, and the WASM bridge does the same thing deliberately: eval renders a caret into source the user typed, while every cast strips the span, because it would name a line and column in a string the bridge generated and the user never saw. Pointing confidently at the wrong place is worse than declining to point.

ADR-022 had scoped runtime positions out — a Phase 2, deferred, on the grounds that spans on all nine expression variants was a bigger change than parse errors were worth waiting behind. That reasoning holds, and the conclusion still came out wrong, because unbound variable is the error that actually makes a prelude hard to debug. Only two variants can fail at run time: a variable reference, and a call. Give those two a span and you have covered unbound names, arity mismatches, non-callable heads, and every complaint any primitive will ever make — because a primitive has no source of its own, and the call site is the position that helps anyway. Two variants, not nine. The deferred phase was mostly the part nobody needed.

A machine that could always stop

The pausable machine required no new mechanism whatsoever. A CEK machine's entire state is one value; that is what the architecture is. What existed was a loop that owned that value and refused to give it back: run to a result, or exhaust the step budget and return an error, discarding the work.

That shape forced bad behavior on the one host that couldn't tolerate it. The browser evaluates on the main thread, so the budget from Act X was the only defense against a loop that never ends — and using it meant freezing the tab for however long ten million transitions take, then reporting a failure, with no progress shown and no way to stop. The budget was quietly doing two unrelated jobs: deciding how long the host should be blocked, and deciding what counts as runaway code.

Separating them is the whole design. A slice is cooperative — how much work the host will do before it wants control back. The budget stays a safety net against code that doesn't terminate. Running out of a slice is not an error; it hands the machine back and lets the caller decide. Fifty thousand steps per animation frame, and the REPL keeps painting, counts steps as it goes, and cancels when asked. The old entry point survives as five lines that turn a pause back into the error it used to be, so nothing that existed had to change.

What the two acts buy together is more than either alone. The continuation chain was always a call stack; the spans are what make it a readable one. So the REPL gained :step for the cost of a print statement — step count, continuation depth, the expression in flight with a caret under it in your own source, and the enclosing call sites. Tail calls not growing the stack has been a test since Act II, asserted by the absence of a crash. It is now something you can sit and watch not happen.

The feature that would have cost 3×

One thing did not get built, and the reason is the most useful paragraph here.

If an error carries a position, the obvious next want is a backtrace — walk the continuation chain at the moment of failure and list the calls. The chain is right there. It takes about fifteen lines. It cannot be done. step consumes its state by value, so building a trace at failure time means holding a copy of the continuation across every transition, which makes every frame shared — and Act XI's fix depends on every frame being uniquely owned. The reference count would come back as two, the unwrap would fall through to the cloning path, and n-argument application would quietly return to costing O(n²). Nothing would break. Nothing would fail a test. The engine would just be three times slower for a debugging convenience.

The backtrace exists, off a paused machine, where nothing is in flight and reading the chain is free. Which is the same information at a different moment, and the moment is the entire cost difference.

And one cap measured against nothing

Adding a span to every datum made the reader's stack frame about half again as large. Somewhere in the reader is a constant capping nesting depth at 1024, with a comment explaining that it sits far below the overflow point and well above any realistic source. The first half of that was a measurement of a stack frame nobody had written down, taken once, implicitly. Sixteen bytes per datum later it was false, and a legal thousand-deep form no longer fit the two megabytes a Rust test thread gets.

The test caught it — by aborting the process rather than failing, which is what a stack overflow does. And the honest fix was not to lower the cap, because that would have restored the coupling that caused the problem: one number serving as both how much nesting we accept and how much stack we have. The reader now uses an explicit stack, for lists and for the quote prefixes that nest just as freely, so the constant bounds a heap vector and means only what it says. Val's destructor and the list printer had both already been rewritten this way, for this reason. It's the third time.

Measuring that turned up something worse, which is recorded and not fixed: compile is still recursive, and it gives out somewhere between 500 and 750 levels. So the reader accepts 1024 levels of nesting and then the compiler overflows on what the reader just handed it. That is not a regression — it measures identically before this work — and it predates spans by a year of commits. The cap was calibrated against the reader's frame alone, and no test had ever run the compiler at depth. A limit that only one of three stages honors is not a limit; it's a number that happened to be true where someone looked.

Two acts ago the lesson was that careful prose starts to feel like proof. This time the prose paid off, once, in the one place it was written as a warning rather than a description: ADR-035 says don't change this back, it reintroduces an O(n²) clone, and that sentence is the only reason a fifteen-line backtrace didn't silently undo an act's worth of work. Everything else here was a note that described something true. The one that changed an outcome described what would happen if you touched it.

The deleted test deserves a line too. Act XI left behind parse_errors_carry_no_source_position, written to assert a limitation and to fail loudly the day someone fixed it, with instructions in the comment for what to update when that happened. It failed. The instructions were correct. Ten tests replaced it. For a codebase whose recurring failure is documentation that outlives its truth, a test that breaks when the docs go stale is the only version of a note that can't rot — and this is the first act where one of them got to do its job.

Act XIII ⋔

Two ways to fail badly — a failure that took everything with it, and one that said nothing at all

The language had no vocabulary for either situation, so in each case it did the most extreme thing available. A primitive that failed took the entire evaluation down with it, because there was no way to say this failed, recoverably. Two packs defining the same name produced no signal whatsoever, because there was no way to say that name is taken. Loud where it should have been quiet; silent where it should have spoken.

Both came due for the same reason. For eleven acts the engine absorbed new vocabulary without learning anything — that was the thesis and it held. But there are three DSLs now, installed into one machine, running on a public page. These two slices are what that costs: three vocabularies sharing one process, and one of them allowed to fail in front of someone.

The failure that took everything with it

(car '()) returned an error from step, unwound to the driver, and aborted the top-level form. Lisp code could neither catch that nor signal a recoverable failure of its own. The DSLs had already felt the absence and worked around it with sentinels — the mana model answers a shortfall by logging mana-short and returning 0, a number standing in for a condition because there was nothing else to use.

The sharper motivation was a live bug, and it took two clicks to reach. A rune tape of modifiers with no element rune is a legal thing to build in the Spell Lab; world-apply! rejects the resulting ctx. That rejection left the bridge as a JavaScript exception — and because cast! charges mana before applying, the failed cast kept the mana it had spent. One missing feature, two failures: it died badly and it charged you for it.

What went in is unwinding conditions in the Scheme tradition — raise, error, guard — and a third mode in the machine that discards continuation frames until it meets a handler or reaches the halt frame. The detail worth keeping is that it discards one frame per step rather than looping to the handler. That keeps unwinding interruptible and step-counted like everything else, and because each discarded frame drops the environment it held, the store slots those bindings owned come back through the destructor that already existed. Unwinding reclaims as it goes, and there is no line in the unwinder that knows about reclamation. Two earlier acts' machinery paid for this one's feature without being asked.

Everything the machine can fail at is catchable, with one deliberate hole. Prim complaints, unbound variables, arity mismatches, non-callable heads — all of them raise, so there is a single answer to "what can a guard catch" instead of a taxonomy to defend at every new error site. The exception is the step budget from the last act, which never becomes a condition, because a guard that could swallow it would make a runaway loop unkillable — the precise hazard the budget exists to prevent.

A condition is an ordinary list. No tenth Val variant, which keeps values cheap to clone the way Act XI needed them to be, at a cost recorded rather than prevented: a hand-built (error "…") is indistinguishable from a raised one. That is the usual Lisp bargain, and the accessors are the supported way to read a condition rather than the only one.

And there is a bill. This project's pitch is five transition rules. It is now five rules plus a raise mode and two more continuation variants, and no phrasing makes that sentence as small as the one it replaces. What it buys is the single thing sentinels cannot fake — a cast that fails recoverably without taking the interpreter, or the tab, with it.

The failure that said nothing

Every define in the process landed in one table. Spells and genes both define thread; both define assoc-set; the bridge installs all three packs into one machine. Whichever went second won, in silence.

Measured before designing, because the definitions are identical anyway is exactly the kind of claim this log has learned to distrust. It wasn't false — a cast with both packs installed still returned the right answer. Then genes redefines thread to something else and the same cast returns a wrong answer quietly. Then the third measurement settled the design: a closure that had captured the old thread was hijacked too.

The reason is a feature from Act VI. Closures resolve top-level names at call time against the table's current contents — which is what made mutual recursion work across REPL lines, and which means a closure re-resolves its own name on every recursive call. Saving a reference before something is shadowed does not protect you. Shadowing was never containable by discipline at the call site, and that rules out every fix that is really a convention.

So: a namespace is a table plus an optional parent. Each pack installs into its own, chained to a shared root holding the builtins. Lookup walks outward; define always writes to the table it started in, so a pack shadowing a builtin affects nobody else. What makes that lexical rather than dynamic is one sentence — the environment holds the namespace, and closures capture their environment — so a spells closure calling thread gets spells' thread even when a genes closure invoked it.

Publishing a name into the root shares the cell, not the value, so set! through either path writes the same slot. That is what lets the mana counter stay inside the spells pack and still be read from the root by the bridge, which is the grandfathered exception from two acts ago, working unchanged.

The actual fix is the refusal: exporting a name another pack has already exported is an error that names both packs. Silence was always the hazard here — shadowing, contained and announced, is a feature. The visible cost is small and worth stating, because someone will hit it: (thread …) typed into the web REPL now errors, where before it worked by accident.

What the new surfaces reopened

Both went to review and came back with seven defects between them, two serious enough that namespaces did not work as documented. The count isn't the interesting part. What's interesting is how many of them were old invariants that a new surface quietly reopened.

error builds its condition using list, and compiled that as a variable reference — so (let ((list …)) (error "boom")) returned the user's list instead of raising. Quasiquote had the same bug against list and append, and had had it since the day it was written; the review found it on error, and the shared cause made each a one-line fix. The rule generalizes cleanly, which is why it's here: a compiler that emits a variable reference is emitting a name the user is allowed to rebind.

The expander had no branch for guard, so it read the binder (var handler) as an application and expanded var when the name happened to be a macro. Every new binding form needs a matching branch there, and nothing enforces that except a test that thinks to try it.

And the accessor this work added to reach a namespace handed back the namespace itself — letting a caller keep the entire globals table, and every closure and binding cell in it, alive past the machine that owned it. That is exactly the invariant Act XI made the field private to protect, reintroduced two acts later by the API written on top of it. It is now an opaque handle: a name the machine resolves internally, with nothing inside it to hold.

The reinstall defect earns its own paragraph. Installing a pack twice panicked — because re-running a prelude allocates fresh cells, so the second install presented a different cell for a name that same pack had already published, and the check compared cell identity and called that a collision. Export was documented as idempotent. It had never once been idempotent. The fix is to compare provenance instead — which pack published the name — and it fell out of that change for free that a pack exporting car is now refused rather than silently replacing it.

Both of the serious ones had tests. The idempotence test re-exported without re-evaluating the prelude, which is not what a reinstall does. The test named for asserting that a collision names both packs asserted only the half that was present. Each was written against a simplification of the thing it claimed to cover. Each passed.

Which sharpens the last act's lesson rather than repeating it. Act XII ended on the only thing that has ever caught these: running the code and looking at the number. That is necessary and it is not sufficient, because here the code was run, deliberately, by a test written for the purpose — and it looked at the number next to the one that mattered. A test is a claim like the prose around it and goes stale the same way, with one difference that cuts the wrong direction. Stale prose merely sits there being wrong. A stale test reports success.

Act XIV ⊑

The same fix, one layer up — a routine slice, and the boundary it reopened for the second time running

The previous act named this one in its own list of what it left undone: macros were still a single table, the same collision one layer up, and the only place it still survived. This is that, and it is deliberately the same fix — one table per namespace, resolution outward along the chain, an afternoon. Which is worth something on its own. The second application of a design is where you find out whether it was a design or a lucky one-off, and this one transplanted without argument.

So the feature isn't the story. What the slice walked into on its way through is: one bug that had been wrong the whole time and reported by nobody, and one door that had been closed carefully, twice, and left ajar again both times by the convenience written on top of it.

The half that was left

A defmacro registers into the namespace its form was evaluated in and never walks outward — the rule the binding side already followed. A macro call resolves along that namespace's chain, innermost first, so a pack's own macro shadows a root one exactly as its define shadows a builtin. Two packs can now hold different macros under one name, which was the entire point.

The stdlib stays at the root, and the outward walk is what makes that work rather than being decoration: the spell prelude uses and and or, and the browser's curve cast uses begin. Without the chain reaching out, every pack would have to install its own copy of the standard library.

One asymmetry is deliberate and worth defending, because the instinct runs the other way. Bindings needed an export, a collision refusal, and a record of which pack published what — because packs publish into a shared root and can therefore collide there. Macros publish nothing. With no publication there is no collision to refuse, so the entire apparatus has no counterpart here, and building the symmetric half would have meant shipping machinery with no caller. Given that the last two amendments in this project were both about claims nothing exercised, that seemed like the wrong direction to be generous in. So a pack's macros are private, full stop, and defspell quietly stopped being language vocabulary and became spell-pack vocabulary.

And one small refusal to assume. The expander keeps its own tables, so it has to agree with the engine about resolution order; it asks for the chain rather than hardcoding "the pack, then the root." That shortcut is true today. It is true in the way this log has learned to distrust — true where someone looked, and silent on the day it stops being.

The bug the fix walked into

Macro closures captured the root environment. A macro defined inside a pack, whose body called one of that pack's own helpers, reported the helper unbound.

Nothing had ever complained, because the only two pack macros in the tree have bodies of pure quasiquote: they assemble a form and call nothing, so they never once asked what they could see. The feature couldn't have been correct without fixing it — a per-pack macro table whose macros can't reach their own pack is half a namespace — but the bug predates the feature entirely. What the work contributed was the question. Which environment should a macro body resolve against? Nobody had needed to have an opinion before, and so the code had one by accident.

A safe type with an unsafe method

The review found the real one. The new accessor handed back an environment, and an environment could still be asked for the namespace behind it — so a caller could keep a pack's table, its cells, and its recursive closures alive after the machine that owned them was gone. Exactly the sole-owner invariant Act XI made those fields private to protect.

The shape of it is the part worth keeping, because it explains why reading the diff doesn't catch it. An environment holds only weak references. Handing one out roots nothing; that was true before this change and is still true now. Nothing in the new code returns an owning reference to anything. What it returns is a type whose own API could produce one — the escape was one call further on than the line you'd be looking at.

Given one instance, the cheap question is what else shares its shape. The answer was one register over: the same environment could also be asked for the store, upgrading to a strong reference and keeping the whole arena alive on the same terms. That one had been public since the fourth register landed back in Act VII, roughly two months, and no test had ever tried it. It cost one question to find.

The namespace accessor turned out to have no caller anywhere in the engine, so it was deleted rather than made private — closing the escape at compile time instead of guarding it at run time. That makes it the second accessor this type has lost for being the only way something could get out past an invariant. Act XI removed the first: an address accessor added for diagnostic tests and never used by one.

Twice in a row, then, on the same invariant. Act XI made the fields private. The namespaces in Act XIII handed out the table itself. This act handed out something that could be asked for the table. Neither was a careless change; both were small conveniences written on top of a boundary that had already been closed deliberately, by someone who knew exactly why it was closed, and had written it down.

Which suggests the thing to actually take away. Privacy is enforced at the field, once. Every method added afterward is a fresh opportunity to hand back what the field was hiding, and nothing in the codebase asks the question at the moment it matters. A private field is a claim about one line. The invariant it exists for is a claim about every line that returns — and only the first of those is checked by anything.

And the honest note, since the last act ended on tests. No test caught either of these, and no test was going to. Three hundred of them passed throughout, and they were not being lazy: an escape like this isn't a behavior that can come out wrong, it's a reachability — nothing misbehaves until someone writes the line that takes advantage, and nobody had. What caught the first was a reviewer asking whether the new convenience gave anything away. What caught the second was asking the same question about its neighbours. Both are questions rather than artifacts, which is an uncomfortable place to have arrived after two acts of concluding that the fix was better tests — and the three lessons stack rather than compete. Run the code and look at the number. Check that the test is testing the claim and not a convenient neighbour of it. And then accept that some of this isn't a claim about behavior at all, and will keep needing somebody to go and ask.

Act XV ⊥

The half that was easy to check — a mechanism built to the shape of the last two bugs, and the one it couldn't see

The previous act ended on an uncomfortable note: an ownership escape isn't a behavior that can come out wrong, so no test was going to catch it, and both instances had been found by somebody asking a question. This act is what happened when I tried to stop needing somebody to ask.

It went well for about an afternoon.

Making it unsayable

The invariant is that the machine is the sole owner of its globals table and its store, so dropping it releases every binding, closure and frame slot. The two reopenings had both been accessors handing one of those back. So: make the two types unnameable from outside the crate. Then no public signature can mention them, and the accessor that would give one away doesn't compile — the rule stops being a thing you have to remember and becomes a thing you cannot write.

Half of that is the privacy. The other half is one line telling the compiler to treat a public function leaking a private type as an error rather than a warning, because a warning is not an invariant. It earned its keep immediately, on a function that had been public and taking the globals table since the day builtins moved into it.

And I checked it, in both directions, rather than trusting that it worked. Three would-be accessors — handing back the table, the arena, and a weak reference to the arena — all three rejected. From outside, naming either type is a privacy error before you can even try. That is a real improvement and it still stands.

The half it couldn't see

The review came back with one finding, and it went to the root of the claim rather than to a case I'd missed. The lint checks types that appear in public signatures. It has nothing whatsoever to say about a public type that stores one of those containers in a private field.

Which is exactly what the resumable batch from Act XII does. It held the namespace it was targeting, strongly, plus a copy of that namespace's entire table — every binding cell — kept so a failed batch could be rolled back. And that type holds no borrow of the machine on purpose: the whole reason it exists in that shape is so a host can park one between animation frames. Being parkable and being able to outlive the thing you came from turn out to be the same property. Start a batch, drop the machine, and every binding defined beforehand was still alive.

The store, meanwhile, died correctly — its weak back-edges did exactly what they were designed to do. The leak was entirely in the wrapper's own fields, which is the cleanest possible demonstration that the boundary was fine and the thing standing just inside it was not.

One detail deserves preserving. The offending field carried a comment justifying itself: held strong: a session outlives no Vm. That sentence had been false since the act that created the type, written in the same commit that made the type borrow-free specifically so it could be parked. A written justification, three acts stale, sitting directly above the line it was wrong about.

A mechanism shaped like its bugs

Here is the part worth the act. I had two examples of the invariant breaking. Both were accessors. So I built a mechanism that checks accessors, verified it thoroughly against accessors, and wrote that the invariant was now enforced by the compiler.

But the property was never "accessors are safe." The property is "nothing outlives the machine." Signatures were where the last two bugs had happened to be — and because that's where I'd been looking, a signature-checker felt like enforcement. I generalized from the instances instead of from the claim, which is a smaller step and looks identical from the inside.

The second attempt checks the property rather than a proxy for it. The machine's destructor counts the outstanding references to its own containers, and if anything still holds one when it goes, that's a failed assertion — in every test run, in every debug build, regardless of where the reference is held from or what type is holding it. No enumeration of wrappers, because enumeration was the mistake. It steps aside while a thread is already panicking, so a failing test keeps its own diagnostic instead of dying in a destructor.

And fixing only the batch type would have been the same error a second time: closing the instance I'd been shown while the class stayed open. So both landed together — the snapshot moved to the machine that owns everything anyway, and the destructor check went in behind it. Four tests pin the guard, three that must trip it and one ordinary machine with two packs and a completed batch that must not. The last one matters as much as the others: a guard that fires on correct code isn't a guard, it's a flaky test.

So the lesson, which is new and which I'd rather have learned some other way: when you finally stop relying on vigilance and build the mechanism, you will build the one that checks what is easy to check. Tools answer the question they answer. That question resembles yours closely enough that the difference survives a careful review of the tool, an honest verification pass, and a written-down decision — because all three of those examine whether the mechanism works, and the mechanism worked perfectly. It was aimed slightly to the left.

Which makes four acts with four lessons that are all the same lesson wearing different clothes, and it took until the fifteenth to see it. Act XII checked careful prose instead of the number. Act XIII checked a convenient neighbour of the claim instead of the claim. Act XIV checked behaviors when the thing wasn't a behavior. This one checked signatures when the thing was never about signatures. Every time, the work was real and the checking was real, and the gap was between what was claimed and what was actually looked at. That gap doesn't announce itself, because from the inside you are always looking at something.

And this act's mechanism is presumably also partial, so the honest close is to say where. The destructor check fires at drop time, in debug builds, and only if something actually drops a machine — so it says nothing about a host that never does, and nothing at all about reference cycles inside a machine that's still running, which remain a known and separate residual. It is a better mechanism than the one before it. It is not the last word, and the pattern of this log is that saying so out loud is the only thing that has ever helped.

What comes after

The substrate is in place — and now it's a substrate with three consumers, which makes the next moves both clearer and less urgent than they looked on day one. The shortlist:

  • Macro export. Macros got their per-pack tables (ADR-043), but a pack still can't publish one: they're private, full stop, so defspell resolves inside the spell pack and nowhere else. Nothing needs more yet. The first pack that wants user-typeable syntax — defcodon, defstroke — is when to build it, against a caller rather than a guess.
  • A declarative (export …). Export lists are hand-written Rust consts today, so a pack that adds public vocabulary and forgets to list it fails at the call site rather than at install. Moving the declaration into the prelude moves the failure earlier.
  • A cleanup hook. There is no dynamic-wind or unwind-protect, so a raise crossing a frame that acquired something releases nothing. Nothing in-tree is exposed — host prims are single-call and effectively atomic — but the first multi-step host effect that needs a release path will want this, and the guard frame is what it gets built on.
  • Restarts. Act XIII's alternative 1, deferred rather than rejected. The handler would run before unwinding and could resume the failed computation with a substitute value. That is expensive in most languages because the stack has to be kept alive, and nearly free here, where the continuation is already a value — and it fits the domain better than dying does: a cast that meets an unknown element could substitute 'inert and carry on. guard is the unwinding special case of it, so nothing already built would have to be undone.
  • A depth cap the whole pipeline honors. The reader accepts 1024 levels of nesting; compile is still recursive and overflows between 500 and 750 (see Act XII). Either an iterative compile — the reader, Val's destructor and the list printer have all gone that way already — or a second, lower cap at compile time. Matters at the untrusted boundary, which is the web REPL.
  • Serializable state. The other half of ADR-001's claim, and the half pausing didn't need. A state can't be written out while Val::Prim holds an Rc<dyn Fn>, so this wants a story for host closures first. Adjacent to the persistent Store below; both are what "time-travel debuggable" would actually cost.
  • Steps as a cost signal. The machine now reports what a form cost to evaluate. Mana prices casts from a hand-written table with no relationship to work done. Metering it by transitions instead is a one-line change to the gate and a different game — noted, not proposed.
  • A real spell library. defspell as a macro shipped with ADR-025 (see Act VIII), but the host-side modelling is still ahead — registering vocabulary under a rune table, element conflict resolution as a strategy passed to the resolver, the "fork into two effects" behavior the design has been hinting at since day one. The substrate's ready; what remains is host-side rules, not syntax.
  • The second adopter. defcodon for the genes prelude or defstroke for curves. Same pattern as defspell; mostly mechanical. Neither is urgent — but each one closes the "is the macros stdlib load-bearing?" question one DSL further.
  • Hygienic macros, or not. An honest pass at gensym + a renaming scheme; or a deliberate decision that unhygienic procedural macros are fine for this codebase and a documented convention is enough.
  • Persistent maps. When the alist outgrows the cons-list, a Val::Map backed by a small persistent structure. Both DSLs use alists; both are comfortable below ~30 keys; this isn't urgent.
  • The play loop. Turn-based render, input → spell → world tick → next state. The game part. The lisp and host-state pieces are in place; this is mostly UI.
  • What CESK opens. set! was the first of these to land (Act IX, ADR-026), and it pulled a whole arc behind it — decay, mana, aftershocks. What's left of the list is the same shape: an undo button or replay scrubber for the labs, reactive bindings, a persistent Store for cheap snapshots — "deferred until a host pulls" entries the store register makes cheap, ready when the use case shows up.

Crossed off since day one: the WASM bridge (crates/wasm/ plus a four-page web shell — landing, Spell Lab, Gene Lab, Curve Lab), installable preludes (ADR-014), the numeric tower, mutual-recursive top-level defines (within and across eval_str calls, after ADR-015 broke the top-level Rc cycle), the genes vocabulary itself. Then the 2026-05-29 audit refactor sequence: the spell + genes packs moved to sibling crates (ADR-016), the engine went host-agnostic via closure-capable prims (ADR-017), and world.rs moved to its own micro-crate (ADR-018). A third sibling vocabulary — L-systems → turtle → ASCII canvas — landed the same day as crates/curves/ (ADR-019), proving the substrate carries a third DSL the same way it carried the first two. Then ADR-020 collapsed the prim frame chain into the same globals table user defines live in, removing the last asymmetry in top-level lookup. The lisp crate is "engine + parser + numeric tower" — zero host types, zero demo vocabulary. And then, on 2026-06-02, the letrec Rc cycle that ADR-021 pinned dissolved via ADR-023 — the engine became CESK, a store joined the three registers, and frame slots became Copy addresses. ADR-024 (2026-06-04) followed: macros lifted to a sibling crate, the engine reverted to macro-unaware, and a small install_stdlib shipped begin / when / unless / and / or on top. Then ADR-025 (2026-06-05): the spell prelude became the first DSL to adopt the stdlib pattern via defspell / defparam, which surfaced and fixed a latent top-level / expression-position confusion in the expander. Then the dynamic-spells arc (ADR-026 through ADR-030) taught the world time and state — set!, tile decay, a mana budget, aftershocks, and element alchemy — and ADR-031 added strings as the ninth Val, all without touching the five rules (see Act IX). Then, on 2026-07-29, the two oldest unspent claims came due together (Act XII): ADR-039 gave errors source spans and a caret, and ADR-040 handed the run loop to the caller — so evaluation can be sliced, resumed, single-stepped and cancelled, the web REPL no longer freezes the tab to protect it, and the REPL grew a stepping debugger for the cost of a print statement. Then, the next day (Act XIII), the two failure modes three DSLs on a public page had made unaffordable: ADR-041 gave the language raise / error / guard, so a cast can fail recoverably instead of taking the interpreter with it, and ADR-042 gave each pack its own binding table chained to a shared root, so spells and genes can both define thread and a collision in the names they publish is refused out loud rather than resolved in silence. ADR-043 finished that job the next day (Act XIV), giving the expander one macro table per namespace so the last place the old collision survived is closed — and turning up two things on the way that nobody was looking for: macro bodies had been resolving against the root rather than against the pack that defined them, and the environment type had two public methods that would upgrade a weak back-edge into a strong one, letting a caller outlive the machine holding either the globals table or the store. ADR-044 (Act XV) closed that second thread for good, or at least for better: the two containers can't be named outside the crate at all now, so the accessor that hands one back won't compile — and, once the first attempt turned out to check only the signatures it had been built to check, the machine's destructor asserts that nothing outlives it. None of the remaining items are large; all of them are interesting; most of them are independent. The hard parts are done — the language is itself, three DSLs proved it, the substrate grew the register it needed, and macros found their crate.

Further reading: CEK, CESK, and friends

  • Matt Might · Writing an interpreter, CEK-style — a clear walkthrough of the three registers, the transition rules, and the path from continuations-as-functions to continuations-as-data.
  • Burak Emir · CEK and Control — the CEK machine read against the broader landscape of control operators (call/cc, delimited continuations); useful for placing the let-rs continuation tower in context.
  • Northeastern CS4400 · Abstract Machines II — lecture notes that derive the CEK rules in a short, tutorial form and place them next to a few neighboring machines (CESK, etc.). A good primer before the Might piece, or a refresher after.
  • Bill Hails · CEKF — a working CEK interpreter in C, extended with failure continuations (the "F") for backtracking. Useful as a reference implementation and as a sketch of the shape the machine takes when you push it past pure lambda calculus into a real language.
